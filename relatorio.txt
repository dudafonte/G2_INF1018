=======================================================
 DESCRIÇÃO DA IMPLEMENTAÇÃO
=======================================================

A função cria_func foi implementada em cria_func.c e gera,
dinamicamente, o código de máquina x86-64 de uma nova função
que chama a função original f com os parâmetros configurados
conforme o array params.

O código gerado segue a estrutura:

  1. Prólogo: push %rbp / mov %rsp, %rbp / sub $0x20, %rsp
     Cria o registro de ativação e alinha a pilha para
     permitir chamadas a funções de biblioteca.

  2. Salva os parâmetros PARAM recebidos na pilha:
     Os argumentos chegam em %rdi, %rsi, %rdx (ABI x86-64).
     Como esses registradores serão sobrescritos na etapa
     seguinte, os valores são salvos em -8(%rbp), -16(%rbp)
     e -24(%rbp).

  3. Carrega os valores nos registradores para chamar f,
     tratando os três casos de origem:

     PARAM: carrega o valor salvo na pilha de volta para
            o registrador correto (mov -offset(%rbp), %rXX).

     FIX:   emite o valor diretamente no código gerado.
            - INT_PAR: mov $imm32, %eXX (5 bytes, sem REX)
            - PTR_PAR: movabs $imm64, %rXX (10 bytes, REX.W)

     IND:   emite o endereço da variável no código e gera
            uma desreferência em runtime.
            - movabs $addr, %rax
            - INT_PAR: mov (%rax), %eXX (lê 32 bits)
            - PTR_PAR: mov (%rax), %rXX (lê 64 bits)

  4. Chama f via call indireto: movabs $f, %rax / call *%rax

  5. Epílogo: leave / ret
     O valor de retorno de f em %rax chega intacto ao
     chamador da função gerada.

 BLOCO B - testes que devem FALHAR
-------------------------------------------------------
 
[B1] IND com NULL - SIGSEGV esperado
  RESULTADO: Segmentation fault (core dumped)
  A função gerada tenta desreferenciar um ponteiro NULL
  ao carregar o valor IND, causando falha de segmentação
  imediata. Comportamento esperado e correto.
 
[B2] n=0 - nenhum parâmetro gerenciado
  RESULTADO: os dois subcasos PASSARAM quando não deviam.
  Com n=0, cria_func não configura nenhum registrador,
  mas a função-alvo (mult) ainda recebe os argumentos
  originais via ABI - então o resultado coincide com o
  valor correto por acidente, e o teste não detecta falha.
  Este comportamento é esperado para uma entrada inválida:
  o enunciado não garante erro observável nesse caso.
 
[B3] buffer de 15 bytes - stack smash esperado
  RESULTADO: resultado: 6
             *** stack smashing detected ***: terminated
             Aborted (core dumped)
  O buffer de 15 bytes é pequeno demais para o código
  gerado, que escreve além do fim do vetor e corrompe
  a pilha. O detector de stack smashing do GCC identifica
  a corrupção e aborta o programa. Comportamento esperado.
 
[B4] n=4 - OOB nas arrays internas; resultado errado ou crash
  RESULTADO: Segmentation fault (core dumped)
  Com n=4, o código acessa posições fora dos arrays
  internos (offsets[], salva_hi[], fix_op[]), gerando
  um acesso inválido a memória. Comportamento esperado.
